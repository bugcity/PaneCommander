# 圧縮・展開の実装計画と技術検証

## 調査開始時点（2026-10-21）

CoreはUI非依存の状態・操作要求、InfrastructureはShell/実ファイル処理、AppはWPFとViewModel。F2/Shift+F2は未実装。ファイル操作の排他はMainViewModel.IsFileOperationRunning、通知は開始時TabState.BeginOperationStatus、フォーカス・選択復元はPaneViewにある。進捗バーとキャンセルを備えたアーカイブ処理は新設が必要。既存ErrorLoggerは対象パスと例外本文を記録せず保持期限もないため、アーカイブログには詳細な別イベント形式と30日保持を追加する。設定はAppearanceSettings/JsonSettingsStoreを再利用。

## 比較・検証

- .NET 10標準API: ZIP/ZIP64、TAR/PAX、GZipを読み書きできる。7z、XZ、Zstandardは標準だけでは不足。ZIP名の生メタデータは公開されないため独立解析が必要。
- SharpCompress 0.50.7（MIT、固定版）: 独立Probeで日本語7z作成・再読込とCRC取得を確認。公式fixtureのtar.gz/tar.xz/tar.zstをReader APIでそれぞれ6エントリ処理できた。通常のArchiveFactoryでtar.xzを開く試行は失敗したため、TAR系はデコーダーストリーム＋TarReaderの逐次処理を使う。
- 7zはseek可能な一時ファイルに非solidで逐次作成。SevenZipWriterOptions.LzmaPropertiesで辞書とfast bytesを指定できる。CompressionLevel単独では制御できない。無圧縮はこのWriterでは非対応のためUIで無効、高速1MiB/16、標準4MiB/32、最大8MiB/64を初期評価対象とする。入力データ全体を保持するコードはなく、保持するMemoryStreamは7zヘッダーのメタデータ。
- 7zのRead APIではOpenEntryStreamだけでCRC検証されない。WriteToのExtractionOptions.CheckCrc=trueを用いる。ZIPは独立中央ディレクトリのCRC32と展開データを照合。XZ/Zstd/GZipは終端まで読み、圧縮フレームの検証を完了する。
- 外部7-Zip実行ファイル・SDKは管理対象のネイティブ配布とライセンス同梱が増えるため、上記で要求を満たせるかを優先して実測する。RARはライブラリが読めても製品では拒否。

参照: [SharpCompress 0.50.7](https://www.nuget.org/packages/SharpCompress/0.50.7)、[7z Writer](https://github.com/adamhathcock/sharpcompress/blob/0.50.7/src/SharpCompress/Writers/SevenZip/SevenZipWriter.cs)、[Writer設定](https://github.com/adamhathcock/sharpcompress/blob/0.50.7/src/SharpCompress/Writers/SevenZip/SevenZipWriterOptions.cs)、[MITライセンス](https://github.com/adamhathcock/sharpcompress/blob/0.50.7/LICENSE.txt)。Probeと取得したソースはartifacts/archive-feasibility-20261021内。未検証事項をこの段階で成功としない。

## 構成・処理フロー

1. Coreに形式・レベル・要求・進捗・解析結果・競合・ユーザー判断の契約を追加。
2. InfrastructureにZIP中央ディレクトリ解析、アーカイブcodec、パス検査、容量検査、同一ボリュームの一時領域、バックアップ付き反映、ログを分離。
3. 展開は全アーカイブを事前解析→アーカイブごとの文字コード判断→最終パスと相互競合→ユーザー判断→容量確認→各アーカイブを逐次stageへ展開・検証→バックアップ付き反映。1アーカイブごとに成功を確定する。
4. 圧縮は入力のメタデータ列挙（リンクは除外通知）→ダイアログ→競合判断→同じフォルダーの一時ファイルへ逐次出力→ソース変更検査→構造/件数/サイズを再読込検証→正式名へ反映。
5. Windows上の出力先再解析ポイントを拒否し、反映中はディレクトリと対象ファイルをハンドルで保護する。ロールバックではこの処理が管理する対象だけを復元し、失敗時はバックアップを保持する。名前だけを根拠に削除しない。一時領域の非表示は処理中の登録パスに基づく。
6. Appに圧縮ダイアログ、仮想化したZIP名比較、競合判断、非モーダル進捗・キャンセルを追加。F2/Shift+F2とネイティブ右クリックの独自項目へ接続し、既存排他へ統合。移動・タブ変更後も開始時の宛先を変更しない。
7. 既定1GiBの空き容量しきい値を設定へ追加。ログは起動時30日より古い日次ログのみ削除し、書込失敗で処理を止めない。

## 検証計画・任意機能

形式とレベル、日本語・ZIP符号化/7075/ZIP64、出力先ルール、衝突・一括判断、リンク・不正パス・CRC・容量・キャンセル・外部変更・ロールバック・日時・隠し属性・一時領域、UI排他・ショートカット・選択を自動検証。大容量は必要容量を確認して実施し、メモリは別プロセスで評価する。既存WPF統合と回帰も実行する。

OS停止・電源断後の自動復旧は任意機能として今回は実装せず、通常のエラー・キャンセルのロールバックを優先する。復元失敗時のバックアップは保持して場所を通知する。実装途中の制約や未実施試験は最終報告へ明示する。

## 実装結果（2026-10-21）

圧縮・展開を実装した。アーカイブは通常ファイルとして扱い、内部の仮想閲覧は追加していない。形式の制約は以下のとおり。

| 形式 | 圧縮 | 展開 | 検証 |
|---|---|---|---|
| ZIP / ZIP64 | 無圧縮・高速・標準・最大 | 対応 | 全レベル、日本語、UTF-8フラグ、CP932、7075、曖昧な名前、65,536エントリ、4GiB超 |
| 7z | 高速・標準・最大 | 対応 | 全対応レベル、日本語、空フォルダー、日時、CRC付き逐次読込 |
| TAR | 対応（レベル対象外） | 対応 | 日本語、階層、空フォルダー、日時、属性、リンク拒否 |
| tar.gz | 無圧縮・高速・標準・最大 | 対応 | 全レベル、階層、空フォルダー、日時、属性 |
| tar.xz / tar.zst | 対応外 | 対応 | 独自fixtureの日本語・空フォルダー、破損・フレームチェックサム拒否 |
| RAR / 暗号化 / 分割 | 対応外 | 拒否・対象外 | ZIP暗号化フラグ拒否、形式の制限。全暗号化・分割実物の網羅試験は未実施 |

### 変更箇所

- Core: `ArchiveOperation`で形式・要求・進捗・競合・文字コード選択の契約。`TabState`で開始タブの進捗と生成物の選択要求。`AppearanceSettings`で既定1GiBの容量しきい値。
- Infrastructure: `ZipNameMetadata`、`ArchiveCodec`、`ArchiveStorage`、`ArchiveTransaction`、`ArchiveService`。64KiBバッファ、逐次処理、同一ボリュームの一時データ、事前競合と容量確認、ハンドルの同一性検査、バックアップ・復元。
- `FileSystemService`は登録済みの一時パスのみ一覧から除外。名前のパターンだけでは除外・削除しない。
- `ErrorLogger`は日次の詳細アーカイブログと30日保持。復元完了・未完了と保持場所を別イベントとして記録。
- App: `ArchiveDialogs`、`MainViewModel.Archives`、`MainWindow.Archives`と既存Fキー・Shellメニュー・ペイン下部表示への統合。処理中の共有排他と終了時のキャンセル待機。背景タブの再読込後も生成物の複数選択を適用。
- 依存: SharpCompress 0.50.7を固定追加。配布物に`THIRD-PARTY-NOTICES.md`を同梱。
- テスト: ArchiveService/ZipMetadata/Safety/Rollbackと実WPF統合のArchive checks。再現可能な大容量・メモリProbeを`tools/PaneCommander.ArchiveProbe`へ追加。READMEのキー一覧・使用方法を更新。

### 安全性と設計判断

展開前に全アーカイブの解析・文字コード・既存/相互競合・必要容量を判定する。処理はアーカイブごとにstageへ全件展開してCRCや利用可能なチェックサムを確認し、反映を始める。事前解析後の外部変更はID・ボリューム・サイズ・更新日時・属性を再照合し、上書きしない。Windowsが後から自動設定するArchive/Normal属性は内容変更判定から除外する。

出力先とstageの親をハンドルで保護し、再解析ポイントを開かない。フォルダーのバックアップ移動ではWindowsの制約により子のハンドルを一旦閉じる必要があるため、移動直後に全子項目の同一性・メタデータを再照合し、検証前に新しい成果物を配置しない。反映の途中で失敗した場合はそのアーカイブだけ復元する。復元先に外部のファイルができた場合はそのファイルを消さず、必要なバックアップを保持して場所を通知する。

圧縮では入力ディレクトリも読み取り用ハンドルで保護し、シンボリックリンク・ジャンクションを辿らない。圧縮後は一時アーカイブの件数・名前・種別・サイズを再読込して通常検証し、元データ全体の再展開比較は行わない。

Releaseビルド成功。全回帰198件のうち192件成功・6件スキップ・失敗0件（`regression-complete.trx`）。新規アーカイブ33件はすべて成功（`archive-final-verified.trx`）。最後のUI修正は実WPF統合も再試験して成功（`archive-wpf-verified.trx`、38秒）。198はデータ行ごとのテスト件数で、1つのWPF統合テストには複数のUI検証を含む。

環境条件付きの既存6件はUNC実機試験、UNC監視、シンボリックリンク権限、実クリップボードなど。失敗や未実施を成功件数へ含めていない。

メモリは別プロセスの処理前値との差。Working SetはOSのプロセスピーク、Private Bytesは進捗ごとの標本。今回の測定は256MiB目標内で、ファイルサイズに比例した増加は観測しなかった。ただし全コーデック・大量メタデータ・高エントロピー入力・全外部アーカイブの上限を保証する測定ではない。ProbeのJSONに生値と時間を保存した。

### 制約・未実施の区別

- 実装済み: 指定4形式の圧縮・6形式の展開、F2/Shift+F2/右クリック、ZIP名の全体判定と比較選択、事前競合と一括判断、容量しきい値、逐次ストリーム、進捗とキャンセル、通常失敗のアーカイブ単位の復元、属性/日時、ログ、生成物選択。
- ライブラリ制約: 7z Writerは無圧縮を公開しないため無効表示。Hidden/System属性を渡す公開APIもないため7z作成時は保存しない。7z読込は記録済みの対応属性を復元する。必要なら属性を渡せる別バックエンドへ変更することが代替案となる。ZIPの日時精度はDOS形式の2秒・ローカル時刻、外部TARのWindows属性は記録がなければ復元しない。
- 任意機能の未実装: 異常終了・電源断後の自動復旧。通常エラー・キャンセルのロールバックと復元不能時の保持を優先した。
- 未実施: アーカイブ機能そのもののUNC書込、ACLによるアクセス拒否の網羅、物理ディスクを実際に満杯にする試験、全形式の4GiB超ファイル、全方式の最大メモリ、異常終了注入、各社の暗号化・分割アーカイブの網羅。容量不足と読み取り不能は注入/排他ファイルで試験した。
- 既知の不具合: 上記試験の範囲で未解消の失敗はない。特殊形式・特殊ファイル・再解析ポイント経由の出力は安全のため拒否し、汎用の専用ソフトウェアへ委ねる。
- 保全: `releases/PaneCommander-20261017-icon/`の9ファイルは既存SHA-256すべて一致。今回の配布出力は別の`releases/PaneCommander-20261021-archives/`へ保存した。

全仕様・全条件での保証済みとはしない。実装済み、制約による部分対応、任意の未実装、未検証を上記のとおり区別する。
