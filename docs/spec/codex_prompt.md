# Codexへの実装指示

このディレクトリの `requirements.md` が要求仕様の正本です。Windows 11向け、C# / .NET 10 / WPFの「PaneCommander」を新規作成してください。

## 実装の進め方

1. `requirements.md`を最後まで読み、要求ID（FR / NFR / AT）に対応する実装・検証計画を `IMPLEMENTATION_STATUS.md` に作成する。
2. **M1のみを最初の実装範囲**とする。全機能を一度に作ったことにしない。M1のビルド・テスト・手動確認項目の整理が完了したら、その状態を明示する。
3. M1では「2ペイン・左右独立タブ・実フォルダ表示・移動・論理的アクティブペイン・明瞭な表示」を動かす。未実装のボタンは機能するように見せかけない（非表示または無効化し、状態を説明する）。
4. その後M2→M3→M4の順に実装する。**各マイルストーンの境界でビルドとテストを実行**する。環境によってGUIテスト不能なら未検証と記録する。
5. 一覧の入力フォーカスと「論理的アクティブペイン」を混同しない。ショートカットがどのペインを対象にするかを明示的な状態とテストで保証する。
6. UIの使いやすさについて主観で勝手に簡略化しない。特にアクティブ側の太枠、ACTIVEラベル、色の独立設定、相対日時色分け、復元、左右タブ独立性は省略不可。
7. ファイル操作について、永久削除・無断上書き・部分失敗の成功扱いを禁止する。実装に必要なAPIが不明ならWindows公式APIを確認し、代替手段を採用する前に制約として記録する。
8. `dotnet build`、`dotnet test`など実際に実行したコマンドと結果を記録する。成功していないテストを成功扱いにしない。
9. 仕様を変更する場合は `DECISIONS.md` に理由と影響対象の要求IDを記録する。未確定要件を推測で確定しない。

## 出力してほしい成果物

- ビルドできるVisual Studioソリューションとソースコード。
- `README.md`（必要環境／ビルド／実行／ショートカット）。
- `IMPLEMENTATION_STATUS.md`（MとFRの進捗、ATの結果、未完了項目）。
- `DECISIONS.md`（仕様判断・制約、実装上の注意）。
- テストコードとテスト実行結果。

最初の実行ではM1まで進め、完了・未完了・検証未実施を区別して報告してください。
