# PaneCommander 要求仕様書（Codex入力用）

- 文書バージョン: 1.0
- 対象: Windows 11 デスクトップ
- 目的: Midnight Commander（mc）の明確な操作対象・キーボード操作・表示の調整自由度を、GUIの2ペイン・タブ・カラム表示・視覚的な情報表現と統合する。
- 性格: **既存製品の外観の模倣ではなく、利用体験を要件として再実装する独立アプリ**。
- アプリ仮称: PaneCommander

## 1. 最優先の設計原則

1. **現在の操作対象は常に明確**：左右のどちらがアクティブか、キーボード操作前に一目で判断できる。
2. **状態が継続する**：再起動しても作業場所・タブ・表示状態・設定が残る。
3. **視認性を利用者自身が調整できる**：フォーカス色、選択色、文字・余白、日時の色分けを変更できる。
4. **ファイルを勝手に失わない**：削除・上書き・移動などは対象と結果を確認できる。無断上書きしない。
5. **2ペインが主役**：左右ペインは互いに独立した作業場所を持ち、アクティブ側が操作元、反対側が既定のコピー・移動先となる。

## 2. 実装技術・動作範囲

- 言語: C#。
- UI: WPF / XAML、MVVMパターン。
- フレームワーク: .NET 10（Windows向け、LTS）。
- 対応OS: Windows 11 x64。
- 配布: 管理者権限が不要な自己完結型（self-contained）ビルドを目標とする。単一EXE化は必須でない。
- データ保存先: `%LOCALAPPDATA%/PaneCommander/`。
- 設定・セッションはJSON。パスに日本語・空白・Unicodeを許容する。
- 永続設定に秘密情報は持たない。テレメトリやクラウド同期は実装しない。
- 重要なビジネスロジック（日時分類・状態遷移・ファイル操作の検証）はUIから分離してテスト可能にする。
- 初期版で扱う対象: 通常のローカルファイル・フォルダ。UNC、再解析ポイント、権限・ロックなどの特殊ケースは**誤処理せず検知して知らせる**ことを優先する。

## 3. 画面構成

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ メニュー / ツールバー                 [設定]                                           │
├───────────────┬─────────────────────────────────┬──────────────────────────────────────┤
│ お気に入り     │ 左ペイン  ● ACTIVE               │ 右ペイン                            │
│               │ [tab A] [tab B] [+]              │ [tab C] [tab D] [+]                 │
│ > 作業        │ [戻る] [進む] [上へ] [パス...]    │ [戻る] [進む] [上へ] [パス...]       │
│ > ダウンロード │ ─────────────────────────────── │ ─────────────────────────────────── │
│ > NAS         │ 名前     サイズ    更新(相対)   │ 名前      サイズ     更新(相対)    │
│               │ file1        ...    5分前       │ backup           ...   3日前       │
│               │ file2        ...    2日前       │ archive          ...   1ヶ月前     │
│               │                                 │                                      │
├───────────────┴─────────────────────────────────┴──────────────────────────────────────┤
│ F3 表示 | F5 コピー | F6 移動 | F7 新規フォルダ | F8 ごみ箱     [状態/エラー]          │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 3.1 左側サイドバー

- お気に入りフォルダを一覧表示する（ツールバーより広い概念として、縦型のサイドバー）。
- サイドバーの表示・非表示と幅を変更できる。
- お気に入りを押すと**その時点のアクティブペインのアクティブタブ**でフォルダを開く。
- お気に入りの追加、名称変更（表示名のみ）、削除、順序変更を提供する。
- 存在しない場所を選んだ場合、エラーを表示して現在の作業状態を壊さない。

### 3.2 左右ペイン

- 左右を常に同時表示する。分割境界はドラッグで変更でき、幅を復元する。
- 各ペインは独立したタブ列、現在のパス、戻る/進む履歴、選択状態を持つ。
- タブの追加、閉じる、切替が可能。各ペインに最低1タブを常に残す。
- タブ追加時は現在のフォルダを引き継ぐ。
- フォルダ内の移動、親フォルダへの移動、アドレス入力に対応する。
- 起動時の初期フォルダは左・右ともユーザーのホームディレクトリ。セッション保存後はそちらを優先する。

## 4. 機能要件

### FR-01: アクティブペインの視認性（最優先）

- アクティブなのは左右どちらか**常に一方だけ**とする。
- アクティブ側はペイン全体の**明確な太枠（初期値3px）**、ヘッダー背景、`ACTIVE`表示で判別できるようにする。
- 非アクティブ側は別の配色とし、一覧の選択状態は残すがアクティブ側と見分けられるようにする。
- 色だけに頼らず、`ACTIVE`の文字・枠線の強調などを併用する。
- ペイン内のクリック、タブのクリック、`Tab` キーでアクティブ側が切り替わる。
- ツールバー、サイドバー、ダイアログへ一時的に入力フォーカスが移っても、**論理的なアクティブペインは維持**する。
- コピー・移動等はWPFの`Keyboard.FocusedElement`だけでなく、この論理的なアクティブペインに基づいて実行する。
- テーマ設定画面で、アクティブ枠線の色と太さ、ヘッダー色、非アクティブ背景、選択行の色を変更できる。

### FR-02: 詳細一覧とOpen／Edit（2026-10-17確定）

- 詳細一覧のみを提供する。旧階層表示はView・ViewModel・状態・切替UI・専用コード/テストを含め廃止する。
- 名前／種類／サイズ／File Age／更新日時を表示し、左右独立の列設定・並べ替え・フィルター・複数選択を維持する。
- Enterと左ダブルクリックは共通のOpen処理を使用する。ディレクトリはアプリ内で移動し、ファイルは拡張子を問わずWindows Shellの既定Openへ渡す。
- EXE／PS1／BAT／CMDも同じ経路。独自のインタープリター呼出しや実行ポリシー変更は行わない。
- Enterは選択済みのフォーカス行1件、行にフォーカスがない場合は主選択1件を対象とする。選択なしでは起動しない。複数選択の一括起動はしない。ダブルクリックは実際にクリックした行1件を対象とし、空白・列ヘッダーでは起動しない。
- F4は単一の通常ファイル選択時のみWindows Shellのcanonical verb `edit`を実行する。選択なし・複数・ディレクトリ・再解析ポイントは無効。Edit未登録/無効や起動失敗は通知し、Openへ代替しない。
- 独自エディター・外部エディターパス設定・拡張子別編集先設定は設けない。
- リンクOpenの既存ローカル検査とShell動作、Shell拡張コマンドのリンク安全制限を維持する。
- DnDはコピー/移動専用。宛先は受信ペインの選択タブの現在ディレクトリ。EXE等の行へのドロップでも起動しない。
- 詳細な移行形式と安全境界は `detail_shell_actions_20261017.md` を参照。

### FR-03: 更新日時の相対表示・色分け

- ファイルの最終更新日時（`LastWriteTime`）を、**現在時刻との差**で相対表現する。例: `5分前`、`3時間前`、`昨日`、`4日前`、`2ヶ月前`。
- 正確な更新日時をツールチップで `yyyy-MM-dd HH:mm:ss` 形式で確認できる。
- 色分けの初期分類（境界の「以下／超」は実装で一貫させる）:

| 分類 | 経過時間 | 初期の意図 |
|---|---|---|
| T1 | 1時間未満 | 最も目立つ強調色 |
| T2 | 1時間以上24時間未満 | 強調色 |
| T3 | 24時間以上7日未満 | 中程度の強調 |
| T4 | 7日以上30日未満 | 控えめな色 |
| T5 | 30日以上 | 標準色 |
| TF | 未来日時 | 警告と区別できる専用色・ラベル |
| TU | 日時取得不可 | `不明` と表示 |

- しきい値、文字色（必要に応じ背景色）、色分けの有効・無効、日時列の表示・非表示を設定画面から変更できる。
- 表示日時は列挙時だけで固定しない。**ウィンドウの再アクティブ化時**と**1分間隔**で再評価する。ファイルシステムを全件再走査せず、取得済みの日時を再分類する。
- 色分けを無効化しても相対日時文字列は表示する。
- 昨日や数ヶ月前などの表現はローカル時刻・日本語設定に基づく。時刻差の境界処理と未来日時のテストを用意する。

### FR-04: タブと作業状態の復元

- 左右の全タブについてフォルダパス、タブ順、選択タブ、ソートを保存する。
- 左右ペインの幅、最後のアクティブ側、サイドバーの幅・表示状態、ウィンドウサイズ・位置、テーマを保存する。
- 正常終了・再起動後、前回作業していた状態を復元する。
- 設定保存は一時ファイルへの書き込み後に置換し、破損しにくくする。読み込めない場合は安全な既定値へ復帰し、理由を通知する。
- 復元対象のフォルダが存在しない／アクセス不可の場合、そのタブにエラーを示す。勝手に別のフォルダに置き換えない（ユーザーが新しいパスを指定できる）。

### FR-05: お気に入り

- 現在のフォルダをお気に入りへ追加できる。
- お気に入りには任意の表示名を指定可能。
- お気に入りはアプリ再起動後も保存される。
- 同一パスの重複追加は原則防止する（Windowsの大文字・小文字のパス比較に注意）。
- お気に入りの選択先はFR-01の論理的アクティブペインとする。

### FR-06: キーボード操作（mc志向）

| キー | 動作 |
|---|---|
| `Tab` | 左右アクティブペイン切替 |
| `Enter` | フォルダに入る／ファイルを既定アプリで開く |
| `Backspace` | 親フォルダへ移動 |
| `Alt+Left` / `Alt+Right` | 履歴を戻る／進む |
| `Ctrl+T` | アクティブペインでタブ追加 |
| `Ctrl+W` | アクティブタブを閉じる（最終タブは閉じない） |
| `Ctrl+D` | 現在フォルダをお気に入り追加 |
| `Insert` | 一覧で複数選択をトグル |
| `F3` | 選択ファイルを読み取り専用プレビュー（対応可能なテキストのみ） |
| `F4` | 単一通常ファイルにShell Edit（利用不可時は通知、Open代替なし） |
| `F5` | アクティブ側の選択項目を反対ペインの現在フォルダへコピー |
| `F6` | アクティブ側の選択項目を反対ペインの現在フォルダへ移動 |
| `F7` | アクティブ側の現在フォルダに新規フォルダ作成 |
| `F8` | 選択項目をごみ箱へ移動（確認あり） |

- キー操作は対象一覧を操作中に有効とする。アドレス入力欄など**文字編集中に誤発火しない**。
- F3/F4/F5/F6/F7/F8は画面下部にもボタンとして表示する。
- 主要ショートカットは将来キーバインド変更可能な構成にするが、初版で変更UIは必須でない。

### FR-07: ファイル操作と安全性

- 複数項目の選択、コピー、移動、新規フォルダ、削除（ごみ箱）を提供する。
- F5/F6の既定宛先は**反対ペインのアクティブタブの現在フォルダ**。
- 実行前ダイアログに操作、件数、コピー元、コピー先を表示し、キャンセル可能にする。
- 同名ファイルがある場合は、**スキップ／名前を変更／明示的な上書き**を選択させる。選択されるまでは上書き禁止。
- 同じ元・先、ファイルを自分自身へコピー、ディレクトリの自分自身または子孫への移動・コピーを禁止する。
- 実行中は処理状態を表示し、例外・部分失敗・キャンセルをユーザーに通知する。未完了を成功と表示しない。
- 削除はWindowsのごみ箱経由とする。ごみ箱を使えない対象で**永久削除へ黙ってフォールバックしない**。
- OSのアクセス拒否・ファイル使用中・再解析ポイント（シンボリックリンク／ジャンクション）等は、誤操作を防ぎ、理由を表示する。初版では再解析ポイントの再帰コピーは非対応としてもよいが、その場合必ず明示する。
- UIスレッドを長時間ブロックしない。操作中にUI操作でき、進捗を確認できる。
- エクスプローラー等による外部変更はフォルダ再表示／手動更新で反映できる（リアルタイム監視は初版の必須条件ではない）。

### FR-08: 見た目・操作のカスタマイズ

設定画面で以下を編集し、保存・復元できること。

- ライト／ダークテーマ。
- フォントファミリ・サイズ（ファイル一覧、タブ、ペイン見出し）。
- 行の高さ／表示密度。
- ペインのアクティブ枠色・太さ／非アクティブ色。
- アクティブ側選択行・非アクティブ側選択行の色。
- 日時分類の閾値と各分類の色（FR-03）。
- お気に入りサイドバーと日時列の表示・非表示。
- 設定プレビューを提供し、**適用／キャンセル／既定値へ戻す**を明確に区別する。
- 設定が不正（色コード不正、閾値逆転、文字サイズ範囲外等）なら保存を拒否し、入力項目を指摘する。

## 5. 非機能要件

- **NFR-01 操作レスポンス**: 通常のローカルフォルダ（数百件）を開くとき、列挙処理でUIをフリーズさせない。大量件数では仮想化や非同期読込を使う。
- **NFR-02 失敗時の安全性**: フォルダ列挙失敗や設定JSON破損でアプリ全体が落ちない。
- **NFR-03 視認性**: どのテーマでもアクティブ側を枠＋ラベルで区別し、アクティブ・非アクティブの選択行が混同されない。
- **NFR-04 復元性**: 設定・セッション保存はアプリの通常終了で必ず行う。異常終了時の完全復元は保証対象外だが、可能な限り状態を定期保存する。
- **NFR-05 保守性**: 画面（View）に直接ファイル操作・JSON永続化・日時分類ロジックを混在させない。
- **NFR-06 ログ**: エラーを `%LOCALAPPDATA%/PaneCommander/logs/` に記録する。ファイル本文やプライベートな内容は記録しない。パスは診断上必要な範囲のみ。
- **NFR-07 DPI**: Windows 11の表示スケーリングに対応。高DPIで枠や文字が潰れない。

## 6. 初版の非対象（勝手に実装しない）

- ネットワークドライブ専用の高速化・認証UI、FTP/SFTP、クラウド同期。
- ファイルの内容検索・インデックス生成、アーカイブ編集、重複ファイル検索。
- Windowsエクスプローラーのシェル拡張・コンテキストメニュー完全互換。
- 管理者権限での権限昇格、ファイルシステム監視の完全リアルタイム同期。
- OS標準のエクスプローラー自体の置換。
- 自由なキーバインド編集UI、プラグイン、スクリプト、FTP機能。

## 7. ステップごとの完成条件

**M1: 2ペインとフォーカス**
- WPFアプリ起動、左右2ペイン、タブ、フォルダ表示、パス移動。
- アクティブ側が視覚的に明確で、Tab/クリックの切替と状態保持が正しい。
- 右/左ペインのタブを操作しても反対側のタブ状態が変化しない。

**M2: 視認性とカスタマイズ**
- 詳細一覧、File Age＋色分け（旧階層カラム要求は2026-10-17廃止）。
- 視認性設定、しきい値設定、プレビューと永続化。

**M3: ワークスペース状態**
- サイドバーお気に入り、全タブとウィンドウ構成の保存・復元。
- 無効な復元パス・破損JSONに対する安全な挙動。

**M4: ファイル操作**
- F3/F4/F5/F6/F7/F8と下部アクションバー。
- 選択項目の操作、事前確認、競合処理、部分失敗表示、誤消去防止。

M1から順に完成・検証し、未完了のMを完成扱いしない。M1は「単なる見た目」ではなく**実際にファイルシステムを参照して動作する**こと。

## 9. 実装構造の要求

- `PaneCommander.App`（WPF: Views, ViewModels, テーマ、コマンドとUIイベント接続）
- `PaneCommander.Core`（ドメイン状態: PaneState, TabState, FileEntry, Favorite, RelativeTimeCategory, Settings、操作ルール）
- `PaneCommander.Infrastructure`（ファイルシステム、Windows Shell、ごみ箱、JSONストア、ログ等）
- `PaneCommander.Tests`（日時分類、アクティブ側遷移、タブ独立性、設定の読書き、操作ガード等）

境界ルール:
- UI/ViewModelから直接`File.Copy`・`Directory.Delete`や設定JSONのファイル書込を呼ばない。サービス越しに実施する。
- UIに依存しないコアのロジックは単体テスト可能にする。
- フォルダ列挙とファイル操作はキャンセル対応の非同期APIを優先する。
- `IFileSystemService`、`IFileOperationService`、`ISessionStore`、`ISettingsStore`などをインターフェースで隔離する。
- 外部NuGetへの依存は最小限にする。導入理由とライセンスを記録する。
