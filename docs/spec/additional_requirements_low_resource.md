# PaneCommander 追加要件：常駐時の低リソース消費

- 追加仕様ID: ADD-PERF-01
- 適用対象: `requirements.md` v1.1以降
- 優先度: 最上位の非機能要件（M1から適用）

## 1. 設計思想

**常に起動しているが、メインの作業アプリではない。使っていない間は存在による負担を感じさせず、使うときは即座に操作できること。**

ユーザーが日常的に長時間起動したままにするファイラーとして、非アクティブ時のCPU・メモリ・ディスクI/Oを最小化する。性能を得るためにセッション復元、フォーカスの明瞭さ、操作の安全性を犠牲にしない。

## 2. 追加の非機能要件

### NFR-08: メモリ上限（暫定目標）

Windows 11 x64のプロセス単位で測定する。計測値は **Private Bytes**（プライベートなコミット済み仮想メモリ）を主指標とし、Working Setも参考記録する。数値は実測保証値ではなく実装・検証の目標である。

| シナリオ | Private Bytes の目標値 |
|---|---:|
| 起動・初期描画完了後（2ペイン、各1タブ） | 150 MB以下 |
| 通常利用（各ペイン3タブ、合計6タブ、ローカルフォルダ） | 200 MB以下 |
| 大量ファイル表示（1タブ1万件程度） | 300 MB以下 |

数値を満たせない場合は測定環境・再現手順・測定値・原因仮説を記録し、**達成扱いにしない**。勝手に閾値を緩めたり、仕様を変更したりしない。

### NFR-09: 長時間利用時のメモリ安定性

- タブの開閉、フォルダ移動、表示切替の反復で、不要なView、イベント購読、監視ハンドル、ファイル一覧を残留させない。
- 8時間以上の起動と反復操作で、メモリが操作回数に比例して増え続けないことを観測する。
- 固定のキャッシュを許容するが、アイコンやファイル情報のキャッシュは**サイズまたは件数上限を持つ**。
- ガベージコレクションの強制実行を定期処理や節約策として採用しない。

### NFR-10: アイドル時のCPU・I/O

- 画面を操作せず、監視中のフォルダにも変更がない状態では、アプリ独自の定期ポーリング・全件再走査を行わない。
- アイドル時のCPU使用率は、計測対象PCの**システム全CPUに対して平均1%未満**を目標とする（5分間、ウォームアップ完了後）。
- アイドル時はログやセッション保存による継続的なディスク書き込みを行わない。状態変更時の保存と障害ログは例外。
- 相対日時の色分けを更新するためだけに、全アイテムの頻繁な再描画をしない。必要時のみ可視範囲を更新する。

### NFR-11: 再開時の即応性

- アイドル状態・非アクティブ状態から戻る際、キャッシュ不足を理由にUIスレッドを長時間ブロックしない。
- ペイン切替、タブ切替、選択操作に対する視覚的フィードバックは**通常100ms以内を目標**とする。フォルダの再取得が必要なら非同期で実行し、操作を受け付ける状態を保つ。
- 起動状態・タブとパス・操作対象ペインは維持する。メモリ削減のために作業状態を破棄しない。

### NFR-12: リソース節約の実装方式

- 一覧は仮想化し、ファイル全件分のWPFコントロールを生成しない。カラム表示にも同等の考慮を行う。
- フォルダ一覧は非同期・キャンセル可能とし、タブ切替時は不要になった取得を停止する。
- 非アクティブタブでは、タブ状態・パス・履歴など復元に必要な情報を保持し、表示用の巨大なオブジェクト群は必要に応じて解放する。
- ファイル監視は開いている場所に限定し、不要になった監視を解除する。監視イベントは集約し、変化のたびに全フォルダを再読込しない。
- サムネイルの自動大量生成、常時バックグラウンド索引作成、無制限プリフェッチは初版で実施しない。
- サードパーティ製コントロール導入時は、機能だけでなく常駐時のリソース消費を評価する。

### NFR-13: 継続的な測定と品質ゲート

- M1の時点からプロセスのPrivate Bytes、Working Set、CPU使用率、I/O、ハンドル数を計測する。
- 各マイルストーンで同じシナリオを再計測し、前回からの増減と理由を記録する。
- メモリ・CPU目標の未達、または反復操作での継続増加がある場合、`IMPLEMENTATION_STATUS.md`に**未達**と記載する。計測できなければ**未検証**とする。
- WPFが目標未達でも、その理由だけでWinFormsへの置換を自動決定しない。根拠をまとめて設計判断待ちにする。

## 3. 追加受入シナリオ

| ID | 試験 | 合格基準 |
|---|---|---|
| AT-15 | 初期描画終了後、2ペイン各1タブで測定 | Private Bytes 150MB以下（暫定） |
| AT-16 | 2ペイン各3タブで通常フォルダを閲覧 | Private Bytes 200MB以下（暫定） |
| AT-17 | 1万件程度のローカルフォルダを開く | Private Bytes 300MB以下（暫定）、UI操作可能 |
| AT-18 | 画面表示後5分間、無操作・フォルダ変更なし | 平均CPU 1%未満、アプリ由来の周期的な全件I/Oなし |
| AT-19 | タブの開閉・フォルダ移動を反復し、8時間の長時間試験 | 単調にメモリが増加し続けず、監視ハンドルが累積しない |
| AT-20 | アイドル後にペイン・タブを切替 | 通常100ms以内に操作フィードバック、UIが固まらない |
| AT-21 | 非アクティブタブを多数保持し、再度切替 | フォルダと履歴が復元され、閉じたView等が残留しない |

## 4. 測定方法と報告

- **環境を固定して比較**: Windowsバージョン、CPU、RAM、.NET版、ビルド構成（Release）、表示倍率、対象フォルダ件数を記録する。
- 起動直後の変動を避け、初期描画・ウォームアップ完了後に測定する。Private BytesとWorking Setを混同しない。
- Windows Performance Monitor、Process Explorer、または同等の取得可能な方法でプロセスごとの計測を行う。実行できない環境で数字を作らない。
- 測定結果は `PERFORMANCE_REPORT.md` に、試験ID、環境、手順、測定値、合否、未検証事項を保存する。
- 数値目標は**暫定**であり、試作後の実測に基づき人が改定を承認するまで維持する。

## 5. Codexへの指示

- `requirements.md` の FR／NFR／AT と同等の優先度でこの追加要件を実装・検証すること。
- M1から負荷測定の仕組みを用意し、M2～M4で機能追加によるリソース増を比較すること。
- UI仮想化・キャッシュ上限・解放責務を設計に含めること。
- 性能要件を満たせない場合は、実測と原因を記録した上で未達として報告すること。
